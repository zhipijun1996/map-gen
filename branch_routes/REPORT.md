# 模块多样性与奖励支路优化报告

算法`stable-v4-reward-branches`，实际实现`mapgen/gdscript-candidate-0.5.0+dfec9fbf79b7`。依赖PR #8的0.4.2；基线commit为65f3f151ad1de51de910922e44dc45192f2268fd。旧0.4.1/0.4.2包、Python参考、冻结地图和证据均未改写。本轮没有修改主游戏或map-edit。

## 实际实现

1. 生长候选按源模块限制为最多3个摆法进入18个初选；最终随机池按源模块去重，保留与最佳评分相差不超过12分的最多5种模块。不同位置/镜像不再无限占据候选名额；不强迫明显较差的模块参与随机。
2. 出口收益以0.95递减，重复模块按真实源ID计数；维持repeat=8。生长阶段在25%–75%间逐步将出口加权从1降至0.95；可达开放接口不足主路线目标的两倍时保留至少0.9权重。调整温和，未强制限制枢纽数量。
3. 新增有界奖励支路规划，单条最多3个新实例。分开探索靠近核心接口的归并路线和有合法奖励房接续的折返路线。保留明确、同时可摆放的单房折返候选，防止推测性组合占满检查名额；它们属于新规划器的基础候选，不调用旧算法重试。奖励重复、面积、附近奖励和路线结构参与评分。
4. 生长、闭环、Boss与奖励的现有步骤保留；生长后段仍预留奖励容量，终端阶段实际搜索整条奖励支路。所有新增连接模块输出完整源内容。核心图和规划记录属于独立job，没有全局历史状态。

归并/折返候选均调用原safe_state/valid_reward_state与最终独立审计，保留作者Route、方向、全部镜像、未用Port齿轮封口以及普通/目标奖励空间检查。所有目标和预算仍为32生长、6目标奖励、3主路线、长短边比≤3、90秒、500000候选；没有改变seed或源模块。

支路证明分两段：原分叉→目标奖励、目标奖励→核心接口；中间不能借道其他核心房间。每个新增支路实例必须实际出现在证明路径中，拒绝无用模块填充。独立折返额外要求只有原核心分叉这一处外部挂接。forward_merge只用于同一条预先验证主路径上位置更靠后的目标；其他不同核心位置记为core_merge。不会把“有归并路径”说成“物理禁止倒退”。

最终源版本80个seed全部PASS：上述60个加940001–940020。后20个在初始计划中提前列出，曾用于边界修正前的验证，最终修正后同批重放，因此不再称最终实现的未见样本。没有reroll、删失败或替换seed。

每张成功地图运行原独立源内容/有向图/全部奖励空间审计，并从最终runtime-map/v2重建受核心边界约束的支路证明，检查生产者声明的每条路径边（允许普通奖励节点展开）。旧Python审计仅在深拷贝上投影算法/实现身份并移除新配置参数，以验证未改变的静态合同；这不证明Python能够生成新算法地图，也没有改写原始结果或旧参考预期。

原生job合同32项通过：操作预算、批次确定性、结果快照、完成后幂等、请求快照、取消及共享库隔离、缺库/错误类型、宿主token拒绝、候选预算1在第2次拒绝、原256间隔墙钟预算等。支路图单元7项通过，包括3模块向前归并、2模块折返、禁止隐式反向Route、禁止借核心房间绕行、禁止无用填充和独立挂接。prototype验证及原20个历史seed精确重放通过，含原4个已知拒绝。

## 保留的试验与局限

- aggressive growth校准仅4/8成功：过度削弱出口收益会损害三主路和闭环。完整保留SEARCH_EXHAUSTED与候选预算耗尽。
- 初版完整支路搜索0/2成功；引入显式基础候选后7/8成功，再加入竞争评分窗口和温和收益后8/8及其余32/32通过。
- 加大支路分值/宽度试验8/8成功，但8图均时约4.18秒，非单房仅2条；原对应5条、约3.59秒，不采用。返回支路接续搜索改进后为8条、约3.54秒。
- 首次工具编译错误（fraction类型推断）和中断日志保留，不计作地图算法通过；随后增加编译前置检查。
- 初期未发布试验曾共用裸0.5.0身份；原始记录保留，不能作为恢复身份使用。选定实现采用源码摘要身份及完整20文件SHA，不复用初期指纹。

奖励容量预留目前仍使用单房折返的保守可行下界，随后规划器才搜索更长支路。这会漏掉只有复杂归并支路才能满足奖励目标的布局，也是归并比例仍低的限制；本轮没有声称是完整全局支路规划器。4个原能力/邻居夹具障碍不变，不需要升级模块1.1.1；若扩充可用路线，须由模块作者验证最低能力或消除真实夹具依赖，不能自动补反向路径。

所有结果仅为静态数据验证。生成器不依赖LevelPlan、SceneTree、玩家、钱包或Factory；主游戏装配和物理试玩本轮未运行。没有随机危险或随机布怪。0.5.0保持candidate，不自动合并、部署或替换正式游戏默认。

## 原生与真实Web性能

锁定Godot4.7.2.stable.custom_build.gunman_sd1.ed1daf0bf，二进制SHA `eeaec2b65dc3234168be1e1cbcc89731514bbb78dfb2c1b502920c50830a0638`。四能力原生采用old/new/new/old串行专用对照，每个seed每版2次取中位数；Web采用threaded release、Compatibility、软件Chromium与COOP/COEP，小批advance(1)、每tick软8ms/最多128单位。均为独立数据宿主，不含主游戏装配、审图或工具启动时间。

| 四能力请求 / seed | 0.4.2 varied-v1墙钟秒 | 新候选墙钟秒 |

| Native / 930001 | 5.582 | 3.842 |
| Native / 930007 | 4.795 | 3.312 |
| Web / 930001 | 27.675 | 21.118 |
| Web / 930007 | 24.640 | 22.735 |

Web两seed的advance内active之和分别从15.027/13.550秒降至11.496/11.660秒；墙钟差额包含让帧、渲染和宿主记账，不等于算法CPU。结果快照约5–7ms，完整canonical序列化约59–63ms，分别保存，未并入advance时间。新旧选择产生不同地图和搜索计数，因此这些收益包含搜索策略变化，不能称为同结果的纯计算提速，也不能保证每个seed都快。

预载实现沿用0.4.2，不宣称预载提速。新Web两次完整预载约4.299/4.209秒，每次都验证同一ZIP和成员；通过后的同一库供两job使用。原生/Web完整结果与对应冻结原生向量一致，仅排除generation_seconds；Web独立支路审计通过。真实Web在reward_branches阶段发送trusted Escape，事件时间戳到CANCELLED完成19.875ms（包含排队/观察/解卷），不是仅cancel()耗时。Web真实失败SEARCH_EXHAUSTED且map=null/content_store={}。

Web首次对照使用了空的旧版导出目录，返回404且没有运行算法；中断记录保留，补齐旧版导出并增加文件前置检查后重新执行。实际Web证据只使用web-baseline-final/web-final/web-cancel/web-failure，不把404计入算法性能。
