### 为什么暂不把v7定为整体最好

同40seed中v5/v7共同成功39张，只在这些共同样本比较结构，避免失败样本选择偏差：

| 静态图指标，均值 | v5/0.6.0 | v7/0.8.0 |
| --- | ---: | ---: |
| 核心普通模块的源种类 | 22.74 | 27.54 |
| 重复相邻源模块对次数 | 8.44 | 1.44 |
| 核心实例存在“START可达且后续能到Boss”的图状态比例 | 85.36% | 49.87% |
| 最短完整START→Boss路线经过实例数 | 10.69 | 6.44 |
| 排除奖励支路的最短核心路线实例数 | 10.69 | 7.31 |

v7确实改善了重复搭配，并在成功图严格形成“一条向前归并＋五条多模块折返”。v5的支路大多仍是单房折返，其风格目标不同；没有把v5未满足新增风格记作旧协议失败。v7目前的短Boss路线和较低流程覆盖会削弱整图探索意义。该比例衡量有向声明图中的可访问后续状态，不是物理试玩，也不应解读为从START完全看不到一半模块。

原先共同60seed证据仍原样保留在route_construction/comparison/metrics.json：v5 60/60、v6折返58/60、v6归并13/60、v7 58/60。v7额外全新20为20/20，其80例合计78/80。不能把不同样本数的成功率混排。

针对同一严格归并风格，v7明显优于v6归并；这支持放弃v6“先随机骨架、再强行匹配归并”的路线。当前不建议用v6归并替代现有交付。v6折返可作风格对照，没有在稳定性和重复度上显示全面优势。正式0.4.1没有在本轮重新跑同配置，故没有宣称四候选排名覆盖所有历史算法及正式主游戏。

## 移动齿轮效果与限制

共1016组新增移动齿轮：v5内部228/外部92；v6折返232/72；v6归并64/16；v7 226/86。每张图均达到**上限**8组，不表示必须凑8组；若没有安全位置允许少放/不放。独立检查器逐组检查完整扫掠、玩家扩张、边界对齐、静态碰撞、封口、动态机关包络、作者路线、Port、普通/目标奖励领取区、终端房间及牌位避让，检查新增组的对称局部密度上限，127图通过。

优先级依据共享边界及空闲几何候选，尚没有通过真实玩家动作证明哪个位置是可利用的非法路径。它增加越界风险且保留大片空白，不提供硬边界封锁。已有模块危险没有删减，新危险还需要主游戏接入碰撞、伤害与生命周期。预览只执行往返动画，不是伤害认证。

## 告示牌覆盖与真实来源缺口

合计已建模5376个有向到达视图，放置4381个（81.49%）；实体3513块，其中floor3142、suspended371。到达视图数不等于独立物理岔口数，一块牌可以按不同来向展示不同合法方向。同一出口内部的分流当前未建模，不能声称覆盖整个物理世界的每个岔口。

995个缺口中：788个没有满足现有保守静态条件的地面/悬挂位置，207个没有可标记的图目标。普通和目标奖励都参与提示与齿轮保护，没有只保护六个目标房间。源奖励有441条“地图实例×site”记录未出现在保留Route图中（包括不同地图的同源复用），详见comparison/metrics.json的unmapped_reward_sites，逐条带算法、seed、实例、模块与site；不虚构可达性。样例v7/930001缺M43 visible-cache、M44 upper-cache的图领奖锚点。

真实1.1.0无标准商店目的地。显式商店锚点、回岔口绕路的Boss误报排除等在合成夹具验证，未伪造真实商店。未来map-edit可按这些具体缺口补可选安全牌位、同出口内部决策点及奖励对应Route语义；本轮没有改包、放宽生成检查或要求先全库补大量字段。

- 原生合同43项：批次1/17/128/4096，真实图1/17/128，复制隔离、开关相互不改变另一附加物、预算、取消七个可观测阶段、已完成取消无操作、双job取消隔离、图引用与合成商店。
- 独立Python审计160个原始案例（127张成功图静态检查，33原失败保留）、127个sidecar JSON Schema检查。
- prototype/verify.py通过，20固定seed重放逐件匹配，包括原四个拒绝，旧交付包摘要保持不变。
- 原生最大单次advance：v5 34.554ms，v6折返36.108ms，v6归并24.652ms，v7 23.575ms。导出快照/哈希仍有原子步骤，操作预算不保证毫秒时限。

Web结果见同目录DELIVERY及validation/map-additions-20261105下实际证据。原生不能代签Web，审图动画不能代签物理可玩性。主游戏未修改，实际游玩难度、平台/机关状态、伤害、交互、移动端和不同浏览器均未完成验收。所有旧算法/包/冻结预期保持原样；新增组件不参与原生成身份。
